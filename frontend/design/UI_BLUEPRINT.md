# NOTICE2ACTION — UI DESIGN BLUEPRINT

## 1. Product Identity

**Product Name:** Notice2Action  
**Institution:** ANJUMAN INSTITUTE OF TECHNOLOGY AND MANAGEMENT, BHATKAL  
**Tagline:** From Complex Notices to Clear Actions.

Notice2Action transforms complicated institutional notices into understandable summaries, actionable tasks, deadlines, reminders, and organized information.

The interface must feel like a premium, intelligent, trustworthy AI-powered productivity platform — not a basic college project, generic admin dashboard, or copied SaaS template.

---

## 2. Design Direction

### Overall Aesthetic
- Premium AI SaaS interface
- Modern, clean, sophisticated, and organized
- Visually impressive without being cluttered
- Professional enough for an actual institutional product
- Friendly and intuitive for students
- Consistent across every page

### Color Palette
- Deep Navy: `#11132B`
- Navy Light: `#1B2042`
- Royal Purple: `#6C4BFF`
- Purple Dark: `#5738E8`
- Cyan Accent: `#35C6F4`
- Main Background: `#F5F6FC`
- Secondary Background: `#F8F8FD`
- White: `#FFFFFF`

Use purple for primary actions and selected elements.

Use cyan sparingly for AI-related highlights, accents, and visual indicators.

Avoid excessive gradients, saturated backgrounds, distracting colors, and unnecessary decoration.

---

## 3. Typography

Use a clean modern font system.

Preferred typography:
- Inter
- Plus Jakarta Sans
- DM Sans

Typography must have a clear hierarchy:

- Page title — large, bold, prominent
- Section heading — medium-large, semibold
- Card heading — medium, semibold
- Body text — readable and balanced
- Secondary text — muted but accessible
- Labels — compact and clear

Avoid excessively small text, inconsistent font weights, and unnecessary uppercase text.

---

## 4. Layout and Spacing

Maintain a consistent spacing system throughout the application.

- Spacious layouts
- Proper alignment
- Consistent page margins
- Balanced card spacing
- Clear separation between sections
- No cramped content
- No excessive empty spaces

Content should adapt naturally to different screen sizes.

---

## 5. Sidebar Navigation

Create a sophisticated, modern sidebar with a deep navy aesthetic.

### Sidebar Header
- Notice2Action logo/icon
- Notice2Action name
- Small AI/product indicator

### Navigation

1. Dashboard
2. Upload Notice
3. All Notices
4. Calendar
5. Reminders
6. Settings

### Sidebar Behavior
- Clearly highlight the active page.
- Use Lucide icons.
- Smooth hover effects.
- Subtle active-state background.
- Elegant icon/text alignment.
- Proper spacing between navigation items.
- Sidebar should be collapsible on desktop where appropriate.
- Mobile navigation must use a proper slide-in drawer with backdrop.

### Sidebar Footer
- Institutional branding
- User profile or account information if already supported
- Avoid clutter.

Do not make the sidebar unnecessarily wide.

## 7. Dashboard

The Dashboard is the most important page.

It should immediately help the student understand:

- What notices are available?
- What actions need to be completed?
- What deadlines are approaching?
- What requires urgent attention?

### Welcome Section
Create a visually impressive welcome section containing:

- Personalized greeting, if existing user data supports it
- Short supporting message
- Current date, if already supported
- Subtle premium gradient treatment
- Optional decorative AI visual elements

Keep the welcome area elegant, not oversized.

### Statistics Cards

Display existing statistics where available:

- Total Notices
- Pending Actions
- Upcoming Deadlines
- Requires Attention

Each card should have:

- Icon
- Title
- Main number
- Supporting description
- Subtle visual indicator
- Consistent styling

Do not invent statistics or alter data calculations.

### Important Deadlines

Display important deadlines using attractive, readable cards.

Each deadline should clearly communicate:

- Notice title
- Deadline
- Priority
- Remaining time, if supported

Urgent deadlines must be visually distinguishable without making the entire dashboard red.

### Action Checklist

Display pending actions in a clear checklist.

Include existing functionality for:

- Action completion
- Progress indicators, if supported
- Notice references
- Deadline information

### Notice Alerts

Highlight notices requiring attention.

Examples of existing alert types may include:

- Urgent notices
- Uncertain information
- Warnings
- Penalties
- Missing or incomplete actions

Make alerts noticeable but not overwhelming.

### Cards

- Consistent rounded corners
- Comfortable padding
- Smooth hover states only when appropriate

### Buttons

- Subtle hover and press effects

Secondary:

## 16. Icons

Use Lucide React icons already installed in the project.

Maintain:

- Consistent icon sizing
- Consistent stroke weight
- Appropriate alignment
- Meaningful icon usage

Do not mix multiple icon libraries.

Do not use emojis as substitutes for interface icons.

---

## 17. Animations and Microinteractions

Animations must feel purposeful, premium, and subtle.

Use:

- Smooth page entrance
- Subtle card transitions
- Button hover feedback
- Sidebar transitions
- Modal transitions
- Loading animations
- Progress transitions
- Subtle staggered animation where appropriate

Avoid:

- Excessive bouncing
- Constant floating
- Distracting movement
- Long animations
- Animation on every element

Respect `prefers-reduced-motion`.

---

## 18. Responsive Design

The entire application must be fully responsive.

### Desktop
- Complete sidebar
- Spacious layout
- Organized dashboard grid
- Proper content widths

### Tablet
- Adapted grid
- Reduced spacing
- Collapsible navigation where necessary

### Mobile
- Drawer navigation
- Single-column cards where appropriate
- Proper touch targets
- Responsive forms
- Readable typography
- No horizontal overflow
- Mobile-friendly calendar
- Proper modal sizing

Responsiveness must be implemented throughout the application, not only on the dashboard.

---

## 19. Loading, Empty, Error, and Success States

Every page must account for all relevant states.

### Loading
- Skeleton loaders where appropriate
- Smooth loading feedback
- Avoid unnecessary layout shifts

### Empty
- Helpful message
- Appropriate illustration/icon
- Clear action where applicable

### Error
- Clear explanation
- Retry action when supported
- No technical jargon for students

### Success
- Clear confirmation
- Appropriate feedback
- Smooth transition

Never leave blank spaces where content should appear.

---

## 20. Accessibility

Maintain good accessibility practices.

- Proper contrast
- Keyboard navigation
- Visible focus states
- Accessible button labels
- Semantic HTML
- Accessible form labels
- Screen-reader-friendly status messages
- Reduced-motion support

- React 18
- Vite
- Tailwind CSS
- React Router
- Lucide React
- Existing project architecture

Do not remove existing routes.

## 22. Quality Standard

The finished application must:

- Look like a real premium AI SaaS product.
- Have one consistent visual identity.
- Be visually cohesive across all pages.
- Be polished, modern, and professional.
- Be intuitive for students.
- Work on desktop, tablet, and mobile.
- Have no broken layouts.
- Have no unnecessary visual clutter.
- Have no dead buttons.
- Preserve existing functionality.
- Pass existing linting, tests, and production build.

---

## 23. Final Design Principle

Notice2Action should not merely display notices.

It should make students feel:

**"I know what this notice means. I know what I need to do. I know when I need to do it. And I won't miss anything important."**

The interface must communicate clarity, confidence, intelligence, organization, and trust.

Every design decision should support that experience.
